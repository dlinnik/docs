# Локальный сервер документации Databird

Сервер на Node.js, который рендерит Markdown-статьи этого репозитория в
удобный HTML-сайт. Разворачивается через **Docker Compose** или запускается
напрямую через **Node.js**.

## Быстрый старт — без Docker (Node.js)

Нужен Node.js 18+ (зависимости уже установлены в `docs-server/node_modules`).

**Способ 1 — двойным кликом:** запустите `docs-server\start-docs.bat`.

**Способ 2 — вручную (cmd):**

```cmd
cd /d c:\Users\dl\Desktop\Databird\docs\docs-server
node server.js
```

**Способ 3 — вручную (PowerShell):**

```powershell
cd c:\Users\dl\Desktop\Databird\docs\docs-server
node server.js
```

Сайт откроется на **http://localhost:7080**.

Сервер по умолчанию слушает **только `127.0.0.1`** — наружу трафик
должен проксировать nginx (см. ниже). Чтобы открыть порт наружу
напрямую, задайте переменную окружения:

```cmd
set HOST=0.0.0.0&& node server.js
```

Порт можно сменить переменной окружения:

```cmd
set PORT=8080&& node server.js
```

## Быстрый старт — через Docker

```bash
cd docs-server
docker compose up -d --build
```

Сайт будет доступен на **http://localhost:7080** (nginx на этом же
хосте проксирует на `127.0.0.1:7080`).

### Как работает сеть

В `docker-compose.yml` задан `network_mode: host` — контейнер слушает
сеть хоста напрямую и поднимается на `127.0.0.1:7080` (переменные
`PORT` и `HOST` в compose). Порт **7080 наружу не торчит** — весь
внешний трафик принимает nginx.

> **Внимание:** `network_mode: host` на Windows работает только
> с Linux-контейнерами (Docker Desktop с WSL2). Если вы используете
> Windows-контейнеры, используйте обычный `ports` и `0.0.0.0`.

### Схема (рекомендуемая)

```
Интернет → nginx (443, SSL) → 127.0.0.1:7080 (сервер доков)
```

### Проксирование через nginx

Пример конфигурации nginx (основной сервер, где висит домен):

```nginx
server {
    listen 443 ssl;
    server_name docs.databird.ru;

    # ... ваши ssl_certificate / ssl_certificate_key ...

    location / {
        proxy_pass http://127.0.0.1:7080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Смена порта

Порт по умолчанию — **7080**. Чтобы сменить его, подправьте
переменные `PORT` / `HOST` в `docker-compose.yml` (или в окружении
при запуске без Docker) и перезапустите:

```bash
docker compose up -d --build
```

## Обновление документации

Документация монтируется в контейнер как volume (в Docker) и всегда
читается из файлов репозитория. Достаточно обновить файлы:

```bash
git pull
```

Сервер перечитывает файлы **на каждый запрос** — перезапуск не нужен
ни в Docker, ни без него.

## Остановка сервера

- Без Docker: закройте окно терминала или нажмите `Ctrl+C`.
- Docker: `docker compose down`.

## Как это устроено

| Файл                 | Назначение |
|----------------------|------------|
| `server.js`          | HTTP-сервер: парсит front matter, рендерит Markdown → HTML, раздаёт картинки и строит меню из корневого `index.md`. Порт по умолчанию — 7080 |
| `package.json`       | Зависимость: `marked` (рендер GFM Markdown); скрипты `npm start` |
| `Dockerfile`         | Образ на базе `node:20-alpine`; код и зависимости запекаются в образ |
| `docker-compose.yml` | Порт (по умолчанию 7080) и volume с доками (read-only) |
| `start-docs.bat`     | Запуск сервера без Docker двойным кликом + открытие браузера |
| `.dockerignore`      | Что не попадает в образ |

Статьи открываются по тем же адресам, что и на GitHub Pages:
`/<slug>/`. Картинки внутри статей подключены относительными путями,
поэтому редирект `/slug` → `/slug/` обязателен — сервер делает его сам.

## Примечания

- Файлы статей перечитываются **на каждый запрос** — изменения в доках
  видны сразу, без перезапуска.
- Служебные файлы репозитория (`.git`, `_config.yml`, `CNAME`, сама
  папка `docs-server` и `README.md`) посетителям не отдаются.
- Сервер по умолчанию слушает **только `127.0.0.1:7080`** — наружу
  порт не торчит, внешний трафик принимает nginx (SSL) и проксирует
  на 127.0.0.1:7080. Чтобы открыть порт наружу напрямую, задайте
  `HOST=0.0.0.0`.
- Если nginx выступает на том же хосте, что и контейнер, —
  `network_mode: host` работает «из коробки»: контейнер сразу
  слушает `127.0.0.1:7080` на хосте.
