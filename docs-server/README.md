# Локальный сервер документации Databird

Сервер на Node.js, который рендерит Markdown-статьи этого репозитория в
удобный HTML-сайт. Разворачивается через **Docker Compose** или запускается
напрямую через **Node.js**.

## Быстрый старт — без Docker (Node.js)

Нужен Node.js 18+ (зависимости уже установлены в `docs-server/node_modules`).

**Способ 1 — двойным кликом:** запустите `docs-server\start-docs.bat`.

**Способ 2 — вручную (cmd):**

```cmd
cd /d c:\Users\dl\Desktop\Databird\docs\docs-server
node server.js
```

**Способ 3 — вручную (PowerShell):**

```powershell
cd c:\Users\dl\Desktop\Databird\docs\docs-server
node server.js
```

Сайт откроется на **http://localhost:7080** и будет доступен
в локальной сети.

Порт можно сменить переменной окружения:

```cmd
set PORT=8080&& node server.js
```

## Быстрый старт — через Docker

```bash
cd docs-server
docker compose up -d --build
```

Сайт будет доступен:

- На этом компьютере: http://localhost:7080
- В локальной сети: `http://<IP-адрес-компьютера>:7080`

### Смена порта в Docker

Порт по умолчанию — **7080**. Чтобы сменить его, создайте файл `.env`
рядом с `docker-compose.yml`:

```
DOCS_PORT=8081
```

и перезапустите:

```bash
docker compose up -d
```

## Обновление документации

Документация монтируется в контейнер как volume (в Docker) и всегда
читается из файлов репозитория. Достаточно обновить файлы:

```bash
git pull
```

Сервер перечитывает файлы **на каждый запрос** — перезапуск не нужен
ни в Docker, ни без него.

## Остановка сервера

- Без Docker: закройте окно терминала или нажмите `Ctrl+C`.
- Docker: `docker compose down`.

## Как это устроено

| Файл                 | Назначение |
|----------------------|------------|
| `server.js`          | HTTP-сервер: парсит front matter, рендерит Markdown → HTML, раздаёт картинки и строит меню из корневого `index.md`. Порт по умолчанию — 7080 |
| `package.json`       | Зависимость: `marked` (рендер GFM Markdown); скрипты `npm start` |
| `Dockerfile`         | Образ на базе `node:20-alpine`; код и зависимости запекаются в образ |
| `docker-compose.yml` | Порт (по умолчанию 7080) и volume с доками (read-only) |
| `start-docs.bat`     | Запуск сервера без Docker двойным кликом + открытие браузера |
| `.dockerignore`      | Что не попадает в образ |

Статьи открываются по тем же адресам, что и на GitHub Pages:
`/<slug>/`. Картинки внутри статей подключены относительными путями,
поэтому редирект `/slug` → `/slug/` обязателен — сервер делает его сам.

## Примечания

- Файлы статей перечитываются **на каждый запрос** — изменения в доках
  видны сразу, без перезапуска.
- Служебные файлы репозитория (`.git`, `_config.yml`, `CNAME`, сама
  папка `docs-server` и `README.md`) посетителям не отдаются.
- Сервер слушает `0.0.0.0`, поэтому доступен всем устройствам
  в локальной сети. Если нужно ограничить доступ — откройте его через
  Docker Compose на `127.0.0.1` (`"127.0.0.1:7080:3000"`).
